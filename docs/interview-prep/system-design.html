Where the description and the code disagree

Say these out loud unprompted — it lands better than waiting to be asked
What's claimedWhat's actually builtWhy it's fine for now / what closing the gap looks like
"Review request goes to a queue, processed one by one" Gap asyncio.create_task() per PR — unbounded, concurrent, in-process Fine at low volume. At real volume, a burst of PRs all hit OpenAI's rate limit simultaneously with no backpressure. Close the gap with SQS/Celery, or at minimum an asyncio.Semaphore capping concurrent reviews.
"Redis caching" Gap Redis is provisioned and connected, but the only thing actually using it is the WebSocket pub/sub channel — nothing is cached Not broken, just inaccurately described. Real opportunity: cache the GitHub diff fetch or dedupe identical-diff AI calls. Otherwise, fix the docs to say "pub/sub bus," not "cache."
Webhook URL registration Gap install_webhook() hardcodes http://localhost:8000/... unconditionally, overwriting the environment-aware URL computed one line above it Works only when GitHub can reach literal localhost — i.e. never, without a tunnel. Fix: read the public base URL from settings (ALB DNS / domain in prod, ngrok URL in dev) instead of hardcoding.
Live dashboard updates Partial WebSocket + Redis pub/sub, fire-and-forget — no delivery guarantee if no replica is subscribed at publish time Acceptable because Postgres is the source of truth — a missed live nudge just means the user sees the correct state on next load instead of instantly. Would need Redis Streams or a queue only if the push itself had to be guaranteed.
GitHub access token storage Gap Stored as plaintext Text column on the users row A DB compromise leaks every connected user's GitHub access directly. Encrypt at rest (application- level envelope encryption, or move to Secrets Manager / KMS per-user) before this touches real users.
Failed reviews Gap PR flips to FAILED and stays there — no automatic retry, no dead-letter handling A transient OpenAI or GitHub API hiccup permanently strands that PR until someone notices and manually re-triggers it. Add retry-with-backoff for transient errors, or a "retry" action in the UI.
Auto-scaling infra Live Target-tracking on CPU, memory, and ALB requests-per-target — validated with terraform plan, never deployed to a real account Config is internally consistent; IAM boundaries, quotas, and AZ availability can only be confirmed on a real apply. Say this plainly if asked — don't claim it's running in production.
Observability Gap structlog to CloudWatch Logs — no metrics dashboards, no alarms, no tracing A failure is invisible until someone reads logs or a user complains. Add CloudWatch alarms on ECS task failures / ALB 5xx rate, and basic request tracing across the webhook → worker → WebSocket path.
Automated tests Gap None in the repo — every verification in this project (including the auth-guard race bug) was manual, exploratory QA against a running stack Manual QA found a real bug, which is a fine story to tell — but it doesn't scale and won't catch a regression next time. Add pytest for the backend (RBAC boundaries, webhook idempotency are the highest- value first tests) and basic component tests for the two auth-guarded frontend flows.

If I had one more sprint

Prioritized

Ranked by risk-to-users, not by what's most interesting to build.

  1. Cap concurrent AI reviews Highest real risk — a burst of PRs can silently degrade or fail reviews via OpenAI rate limits with zero visibility into why. A single asyncio.Semaphore is a half-day fix; a real queue is the "correct" version if traffic actually grows.
  2. Fix the hardcoded webhook URL As written, webhook registration cannot work in any real environment, including the production infra this project just built in Chapter 6. Small fix, large functional gap.
  3. Encrypt stored GitHub tokens The one item on this list that's a security issue, not a reliability one — worth fixing before any real user's GitHub account is connected.
  4. Add retry for failed reviews Turns a permanent, silent failure into a transient, self-healing one. Directly improves the thing users actually experience.
  5. Backend RBAC + webhook idempotency tests The two areas already proven to matter this session — RBAC boundaries were manually verified once, webhook idempotency was designed for but never regression-tested. Codify both so they can't silently break later.
